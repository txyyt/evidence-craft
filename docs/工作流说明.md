# EvidenceCraft 工作流：各阶段详解

## ① 报告规格

`config/report_types/company_review.yaml`，一次性配置：章节树与槽位顺序（核心观点固定 4 视角：整体业绩/分业务/行业景气/事件催化）、各槽位论证职责、字数区间、禁用词、行业关键词、范文节选。换报告类型 = 换一份 yaml，代码零改动。

## ② 数据采集

8 个适配器并行拉取，组装为事实包 `facts.json`（37 条标量事实 + 集合数据）。关键数字双源交叉校验（偏差 >0.5% 报警）。**模型不联网、不取数。**

| 适配器 | 内容 | 来源 |
|---|---|---|
| quote | 行情、PE/PB/市值 | 东财 push2 |
| financial | 业绩指标（双源校验） | 东财 datacenter |
| mainop | 分产品/地区收入、毛利率 | 东财 F10 |
| statements | 三表关键科目 ×4 期 | 东财 F10 |
| announcement | 公告全文 + 行业章节摘要（催化/法律/治理分类） | 东财公告接口 |
| consensus | 券商盈利预测一致预期 | 东财 reportapi |
| peer | 同行业估值对比 | 东财板块接口 |
| news | 个股资讯 + 行业新闻扫描 | 东财资讯接口 |

## ③ 大纲规划（LLM ×1）

模型拿到带编号的素材清单，只做三件事：拟结论式标题、为 4 个槽位各拟判断式小标题、**为每条观点勾选引用的事实编号**。不写正文，产出 JSON 施工图 `outline.json`。

## ④ 分节生成（LLM ×6，上下文隔离）

每条观点独立会话：上下文只有该节勾选的事实切片 + 写作规范 + 范文，互不污染。输出强制 JSON（小标题/正文/引用编号）。盈利预测表由代码从一致预期计算渲染，模型不产预测数字。风险提示用镜像法：核心观点依赖假设的反面即风险。

## ⑤ 数字对账（纯代码）

约 80 个合法数字索引（事实 + 主营构成 + 预测表）vs 正文全部数字，容差 0.5% 匹配；被引公告原文进白名单。对不上 = 记入报告；引用不存在的事实 = FAIL。**模型编的任何数字都过不了这一关**（验收：篡改 3 个数字全部被拦，零误报）。

## ⑥ 质量评审（代码 + LLM judge）

- 规则校验器：章节/字数/禁用词/评级合法域、PE 口径互查（自算 PE vs 接口值）；
- LLM judge：对标真研报五维评分（结构/专业性/数据支撑/合规性/可读性），评语须引用原文证据。

不通过 → 只重写点名节（原稿+意见回喂）→ 重新对账校验评审，≤2 轮，仍不达标转人工。

## ⑦ 渲染交付（纯代码）

券商版式 HTML：标题区+评级徽章（规则推算）、K 线头图（本地绘制）、核心观点、盈利预测表、风险提示、**数据溯源附注**（全部事实的来源链）、免责声明。docx 复用同一内容源。
